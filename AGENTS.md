# AGENTS.md

## Platform: Windows + MSVC only
Y-Player builds **only** with MSVC on Windows (`CMakeLists.txt` hard-fails on non-MSVC; `scripts/fetch_deps.py` exits on non-win32). On macOS/Linux you can edit code but **cannot build or run tests** — verify on a Windows host or CI.

## Commands (run from repo root, `cmd.exe`)
- `build`            — Release `.exe` only, no tests; aborts if Y-Player.exe is running (Windows locks the exe)
- `run`              — launch the built exe; forwards file/playlist args
- `build-run`        — build then run
- `scripts\build.cmd [debug|release|relwithdebinfo|ci] [run] [exe]` — fetch deps → configure → build → ctest (`exe` = app only, no tests)
- `scripts\build.cmd ci` — what GitHub Actions runs: Release + clang-tidy (warnings-as-errors) + tests
- `ctest --preset debug -LE integration` — fast unit tests only
- `ctest --preset debug -L integration`  — only the libmpv playback test

First build downloads pinned Qt 6.9.3 + libmpv into `deps/` (gitignored). Requires Python ≥3.10 and VS Build Tools with the C++ workload. Presets: `debug`, `release`, `relwithdebinfo`, `ci`.

## Running one test
`ctest --preset <preset>` handles the environment. To run a single exe directly, use `build\<preset>\bin\tst_<name>.exe` and first put `deps\qt\6.9.3\msvc2022_64\bin` on `PATH` and set `QT_PLUGIN_PATH` to that install's `plugins`.

## Code conventions that differ from Qt defaults
- `QT_NO_KEYWORDS` is defined for every target (`cmake/YpTargetDefaults.cmake`) → use `Q_EMIT` / `Q_SIGNALS` / `Q_SLOTS`, **not** `emit` / `signals` / `slots`.
- Every target compiles with `/W4 /WX /permissive- /utf-8`; clang-tidy runs with `WarningsAsErrors: '*'` under the `ci` preset (`.clang-tidy`).
- `.cmd`/`.bat` files must stay CRLF (`.gitattributes`) — cmd.exe mis-parses LF batch files.
- `.prettierrc.js` (4-space, single quotes) applies to TS/i18n/scripts, not C++.

## Architecture (targets and boundaries)
- `app/` → `y-player`: entrypoint (`main.cpp`), logging setup, bench mode.
- `ui/` → `yp_ui`: Qt Widgets only. Talks to playback **only** through `IPlaybackEngine` (`core/PlaybackEngine.h`) — never to libmpv directly.
- `engine/mpv/` → `yp_engine_mpv`: `MpvEngine` implements `IPlaybackEngine` (ADR-001/003).
- `core/` → `yp_core`: pure logic (state machine, playlist, settings, resume, bookmarks); no Qt Widgets.
- `platform/win/` → `yp_platform_win`: Win32 integration (DXGI info, window styles, file associations).
- `tests/` registered via `yp_add_test` in `tests/CMakeLists.txt`; `tst_mpvengine` is labeled `integration` (600 s timeout) and **skips** (does not fail) when no D3D11 output exists. Test media is committed in `tests/media/` and regenerated by `tests/media/generate.sh` (ADR-013).
